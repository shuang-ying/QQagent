# QQ Agent

一个通过**标准 OneBot v11** 接入 QQ 的 LLM 智能体：自带 Web 管理面板、7 个预设人格、以 QQ 号为唯一 ID 的分层长期记忆、情绪提取与人格调制、分层上下文压缩、图片 / 语音 / 合并转发 / 链接卡片理解、定时提醒与群聊日报，并可在面板里安装和托管 [snowluma](https://github.com/SnowLuma/SnowLuma) 实例。当前发行版本：**2.3.0**。

项目由作者提出需求、进行测试反馈，并在 AI 辅助下开发。发行版不预置 API Key、个人 QQ 号、群号或模型供应商；安装后请先完成模型和权限配置。

> **关于内置 SnowLuma**：上游采用**源码可见非商业许可**（不是开源许可），原生组件另有专有条款。因此**本仓库和 npm 包都不包含 snowluma 的任何源码或二进制**，面板只提供下载、托管与界面集成。你完全可以不用这个功能，直接按原有方式自己运行 snowluma，再让本 Agent 连它的 OneBot 地址。三种接入方式、许可条款分析与离线手动安装步骤见 [内置 SnowLuma 与 Web 终端](docs/snowluma-integration.md)。

## 功能

| 能力 | 说明 |
|---|---|
| **被动回复** | 私聊正常应答；群聊被 @ 或引用机器人时回复，回复对象固定为触发者 |
| **主动插话** | 按消息数量、话题相关度、人格兴趣和可用记忆参与群聊，受概率、间隔、安静时段与每小时上限控制 |
| **统一回复窗口** | 主动与被动回复都纳入上次确认回复之后、本次生成开始前的聊天记录，含排队期间的消息与图片来源 |
| **人格系统** | 7 个预设人格，支持结构化设定、示例对话、群 / 私聊独立人格、切换时保留历史或新开话题 |
| **图片理解** | 合并窗口图片、当前图片与明确引用的旧图，区分发送者；可用独立视觉模型识别资料，再由聊天模型回答 |
| **合并转发** | 读取节点作者、时间、文字与图片，支持嵌套及旧消息引用 |
| **链接与卡片** | 解析 JSON / XML、小程序、音乐等卡片，读取公开静态网页正文；主动、被动和引用问答共享同一份资料 |
| **语音** | 独立 ASR / TTS 模型用途，支持 OpenAI 兼容、Gemini 原生与自定义 HTTP；人格可单独设置音色、语速和朗读风格 |
| **提醒与日报** | 提醒持久化并在重启后恢复；日报只总结目标群已记录的最近 24 小时聊天，支持手动与每日定时 |
| **分层记忆** | 以 QQ 为身份，长期事实、关键词检索、可选向量检索、摘要递归压缩、纠错与遗忘 |
| **情绪系统** | 效价 / 唤醒 / 支配度三维情绪，规则或模型分析，EMA 平滑后影响人格语气与表情包 |
| **表情包** | 可从 QQ 收藏导入、AI 识别含义，模型可在回复中主动发表情 |
| **按用途 Token 预算** | 对回复、识图、表情、情绪、记忆、摘要、日报分别设置输出上限，`0` 保持原有行为 |
| **指令权限** | 每条指令单独设置管理员 / 全部用户 / 用户白名单，中英文别名共用同一份权限 |
| **GitHub 追踪** | 追踪作者公开动态，或订阅指定仓库的 commits / Release，并用 AI 总结更新内容后推送到单独指定的 QQ 会话 |
| **内置 SnowLuma** | 面板内安装、启动、停止独立进程，查看实时终端并使用上游原生界面 |
| **可靠投递** | 会话串行、直接请求优先、消息去重、连接与账号就绪检查、过时主动任务取消、发送结果记录 |

## 环境要求

| 组件 | 要求 |
|---|---|
| Node.js | **最低 22.16.0，建议使用 Node.js 24 LTS** |
| npm | 随 Node.js 安装，用于安装依赖和启动 |
| QQ / OneBot 实现 | 使用 snowluma 等标准 OneBot v11 实现作为服务端；本 Agent 是客户端 |
| 模型 | 一个可用的模型 API；支持 OpenAI 兼容、Anthropic、Gemini、Ollama 等协议 |
| 图片模型 | 可选，使用图片功能时需要真正支持视觉输入的模型 |
| 向量模型 | 可选，语义记忆检索需要可用的 embedding 模型 |
| 语音模型 | 可选，ASR / TTS 需要供应商提供语音接口；普通聊天模型不能代替 |

Windows 提供 `.bat` 启动文件，也可以直接使用 npm 命令。项目使用 Node 内置 SQLite，最低版本依据 [`DatabaseSync.isTransaction`](https://nodejs.org/api/sqlite.html#databaseistransaction) 的可用版本设置，不要用低于 22.16 的 Node 运行。安装后执行 `node -v` 与 `npm -v` 确认。

## 快速开始

### 1. 下载与启动

下载仓库源码并解压，或使用 Git 克隆。

Windows 可双击 **`start.bat`**：首次启动优先按锁文件执行 `npm ci`，依赖不完整时重装，安装失败立即停止并保留错误信息，Agent 的运行退出码也会原样返回。

命令行方式：

```powershell
npm ci
npm start
```

打开管理面板：**<http://127.0.0.1:3081>**。

未配置模型时后台可以启动，此时只显示状态、不能正常回复。请先配置模型和权限，再用 QQ 测试。

### 2. 配置模型

在面板「🔌 模型接入」填写供应商地址与 Key，搜索模型、选中可用模型并设为默认。

「模型用途」区域可以让不同环节使用不同模型：

| 用途 | 作用 | 留空时 |
|---|---|---|
| 主对话 `chat` | 生成聊天回复 | 继承默认模型 |
| 情绪分析 `emotion` | 高频调用，建议用便宜的小模型 | 继承默认模型 |
| 上下文压缩 `summary` | 摘要与递归分层压缩 | 继承默认模型 |
| 记忆抽取 `facts` | 从对话里抽取长期事实 | 继承默认模型 |
| 向量化 `embedding` | 语义记忆检索 | 不启用语义检索 |
| 图片理解 `vision` | 结构化描述图片与 OCR | 继承默认模型 |
| 语音转写 `asr` | 语音消息转文字 | 不启用语音理解 |

API Key 有两种放法，二选一：

- 在 `config/providers.yaml`（或 `config/providers.local.yaml`）里写 `apiKeyEnv: MY_KEY`，再把 `MY_KEY=sk-...` 写进 `.env`（推荐，`.env` 不入库）；
- 直接填在 `config/providers.local.yaml` 的 `apiKey` 字段（该文件同样不入库）。

`.env.example` 是模板，复制成 `.env` 后填写。

### 3. 配置管理员、群和指令权限

在面板「🔐 权限」页设置，比手改配置更直观：

- **管理员 QQ**：管理类指令的使用者，建议**第一次就填好**，否则任何人都能用管理指令。
- **用户黑名单 / 白名单**：黑名单优先级最高；白名单为空表示所有人可用。
- **群白名单**：为空表示所有群可用。
- **群聊是否必须 @**：建议保持开启，避免刷屏。
- **逐指令权限**：`/memory`、`/persona`、`/daily` 等每条指令可分别设为管理员、全部用户或用户白名单。

默认值刻意保守：`commandAdminOnly: true`、`personaAdminOnly: true`、群聊要求 @，主动发言、表情包、分条发送等默认关闭。

### 4. 接入 QQ

本 Agent 作为客户端，以**正向 WebSocket** 接入 OneBot v11 服务端。在实现端启用同时提供 API 和事件的正向 WebSocket 服务端，然后按下表填写：

| 项目 | 值 |
|---|---|
| 类型 | WebSocket 服务端（正向 WS，由 Agent 主动连接） |
| 主机 | `127.0.0.1` |
| 端口 | `3001` |
| 消息格式 | `array` 或 `string` 均可（两种都支持） |
| Token | 若设置了，请同步填到 `config/app.yaml` 的 `napcat.accessToken` |

默认地址是 `ws://127.0.0.1:3001`，改地址请编辑 `config/app.yaml` 的 `napcat.url`。配置节名沿用 `napcat` 只是历史兼容，**不表示必须安装 NapCat**。

具体怎么拿到这个 OneBot 服务端，见下一节。

### 5. 不接真实 QQ 的调试

双击 **`start-mock.bat`** 启动模拟 OneBot 服务端，另开一个窗口运行 `start.bat`，然后：

- 直接输入文字回车 → 模拟群聊 @机器人
- `/p 你好` → 模拟私聊
- `/g 你好` → 模拟群聊但不 @机器人

> **端口冲突**：mock 默认也想用 `3001`。若真实服务端已占用，mock 会自动改用 `3002` 并提示；此时把 `config/app.yaml` 的 `napcat.url` 改成 `ws://127.0.0.1:3002`，否则 Agent 连的仍是真实服务端。

## 接入 QQ 的三种方式

### 方案 A：自己运行 snowluma（推荐，零许可顾虑）

按 snowluma 官方文档自行下载、安装、登录并开启 OneBot 服务端，然后把 `config/app.yaml` 的 `napcat.url` 指向它即可。此时：

- 上游文件的获取、条款确认、更新与账号风险完全由你自己处理，本仓库不分发任何上游内容；
- 面板里的「SnowLuma」页可以不用；
- Agent 只做一件事：作为 OneBot 客户端连上来。

### 方案 B：用面板托管（需要能访问 github.com）

1. 打开面板左侧 **❄ SnowLuma**；
2. 点 **安装内置组件**：后台从 **snowluma 官方 GitHub 发布页**下载固定版本的完整包与同版本源码，校验 SHA256 后解压到 `runtime/snowluma/`；
3. 点 **启动 SnowLuma**，在终端输出里找到首次登录密码，在下方官方界面完成登录、EULA / 隐私确认与 QQ 接入；
4. 在 snowluma 里配置 OneBot 连接，地址与页面显示的 Agent 连接地址一致；
5. 需要停止时点 **停止**。

特点：进程在后台独立运行，刷新或离开页面不会停；Agent 正常退出时会关闭代理并停止受管实例；异常退出会报告退出码，不会无限自动重启。**下载与运行都在你自己的机器上完成**，仓库和 npm 包里没有这些文件。

### 方案 C：离线手动放置官方包

内网或无法访问 GitHub 时，自己下载官方包、核对 SHA256、解压到 `runtime/snowluma/distribution/app/`，并写一个 `installation.json`。完整步骤、校验值和 JSON 示例见 [内置 SnowLuma 与 Web 终端 → 手动安装](docs/snowluma-integration.md#手动安装离线或内网)。

### 三种方式的共同边界

- 不会自动改写 Agent 的 OneBot 地址、认证、模型或既有账号资料；
- 不会接管或停止你此前单独运行的另一个 snowluma，面板只管自己启动的那个；
- 进程或 WebUI 显示「运行中」不代表 QQ 已登录、也不代表 OneBot 已连上，真实状态仍在两个项目各自的界面查看。

## 运行行为

### 被动回复与对象归属

- 私聊：默认任何消息都回复（`trigger.private: always`，也可改成 `keyword` / `prefix`）。
- 群聊：默认要求 @机器人，可以附加关键词或前缀触发。
- 回复对象固定为**触发者**，不会因为群里后面有人说话而改 @ 给别人；引用回复也指向触发那条消息。
- 同一会话两次回复有最小间隔（`cooldownMs`）和并发生成上限（`maxConcurrent`），超出时排队而不是并发刷屏。

### 主动发言

默认**关闭**。开启后由四个因素共同决定是否插话：机会点（每 N 条消息）、话题相关度、人格兴趣、可用记忆。可用 `minIntervalMs`、`minGapAfterBotMs`、`maxPerHourPerScope`、`quietHours` 做上限约束，`onlyWhenAddressed` 可以要求只在被提及时才可能接话。

主动发言与被动回复共享同一份**回复窗口**：上次确认回复之后到本次生成开始前的消息都会进上下文，包括排队期间新到的消息与图片。因此它看得见群里刚发的图，不会只根据半分钟前的旧上下文说话。

### 回复风格

- 分条发送（`reply.segmented`）：把长回复拆成几条，按字数模拟打字停顿；默认关闭。
- `typingDelayMs`：回复前的「思考」延迟，默认 `[0, 0]`。
- `mentionOnReply` / `quoteOnReply`：群里是否 @ 对方、是否引用原消息。
- 戳一戳：`pokeBack` 戳回去、`pokeReply` 说一句，人格可用 `pokeReplies` 自定义。
- 表情回应：`emojiLike` 给消息点 👍。

### 可靠性

会话内串行投递、直接请求优先、消息去重、连接与账号就绪检查、过时主动任务取消、发送结果记录。OneBot 结果未知时**不重复发送**，避免出现重复消息。

## 人格、记忆与情绪

### 人格

内置 7 个预设人格：`catgirl`、`blue-fish`、`cool`、`genki`、`gentle`、`sage`、`tsundere`。可在面板直接新建或编辑，也可改 `config/personas/*.yaml`。

一个人格可以定义：系统设定与结构化的身份 / 性格 / 说话风格、示例对话、`errorMessage`、`pokeReplies`、`emotionModulation`（不同情绪下的语气），以及独立的语音参数。人格可分配到默认、私聊或某个群，切换时可选保留历史或新开话题。

### 记忆

以 **QQ 号**为用户身份，而不是会话：同一个人在群里和私聊里，长期事实是同一份；对话内容本身按群隔离。

- 长期事实：自动抽取喜好、身份、技能、目标等，支持去重、替换、纠错和遗忘。
- 关键词检索：FTS5 + LIKE，带时间衰减。
- 语义检索：配置 embedding 模型后按余弦相似度召回，未配置时自动退回关键词。
- 跨会话共享策略：`identity-facts`（默认，只共享身份类中性事实）、`full`、`none`。
- 摘要压缩：未摘要消息超过阈值后压缩，保留最近原文，支持 L1 / L2 / L3 递归分层。

### 情绪

效价（愉悦度）、唤醒度（激动程度）、支配度（掌控感）三个维度。分析方式 `rule` / `llm` / `hybrid`，状态用 EMA 平滑，再用于本轮回复的语气混合，并与人格的 `emotionModulation`、表情包自动发送联动。

完整机制、隔离规则、默认值与配置示例见 [记忆、上下文压缩、Embedding 与情绪系统详解](docs/memory-context-embedding-emotion.md)；人格结构见 [人格上下文与结构化设定](docs/persona-context-and-structure.md)。

## QQ 内指令

| 指令 | 中文别名 | 作用 |
|---|---|---|
| `/help`、`/?` | — | 查看帮助 |
| `/persona [id] [keep\|new]` | `/人格` | 查看 / 切换当前人格 |
| `/personas` | `/人格列表` | 列出人格 |
| `/memory` | `/记忆` | 查看关于发送者自己的记忆 |
| `/forget <关键词>` | `/忘记` | 删除匹配的、允许访问的本人记忆 |
| `/emotion` | `/情绪` | 查看发送者情绪状态 |
| `/new [标题]` | `/新话题` | 新开话题，旧话题保留 |
| `/topics [序号]` | `/话题` | 列出或切换当前会话话题 |
| `/stats` | `/统计` | 查看机器人统计 |

## 图片、语音、转发与卡片

| 功能 | 要点 | 详述 |
|---|---|---|
| 图片理解 | 窗口图片 + 当前图 + 明确引用的旧图一起交给视觉模型，区分发送者；识图失败仍继续文本回复 | 见下方「常见问题」 |
| 合并转发 | 读取节点原作者、时间、正文与图片来源，支持嵌套 | [阅读合并转发](docs/forward-messages.md) |
| 语音 | ASR 转写不会自动执行指令；TTS 保留文字回复，语音失败不影响文字 | [语音、提醒与群聊日报](docs/voice-and-scheduled-tasks.md) |
| 链接与卡片 | 解析 JSON / XML、小程序、音乐卡片，抓取公开静态网页正文 | [链接与卡片理解](docs/links-and-cards.md) |
| 表情包 | 从 QQ 收藏导入（幂等命名）、AI 识别标签与描述、按情绪或模型决定是否发送 | `config/stickers/README.md` |

外部抓取的网页、卡片文本和他人昵称都属于**不可信输入**：会被转义成普通消息段，`[CQ:at,qq=all]` 之类的注入不会生效，也不会被当成系统指令或记忆归属。

### 关于模型能力判断

模型是否支持图片是按模型名推断的，中转站改名后可能判错（例如把不支持视觉的模型叫成 `xxx-vision`）。判错时在 `config/app.yaml` 里覆盖，不用改代码：

```yaml
llm:
  modelOverrides:
    "deepseek-v4.1-flash": { vision: true }
    "some-old-model": { vision: false }
```

## GitHub 动态追踪（作者 + 仓库订阅）

面板「📡 GitHub 追踪」页支持两种可以并存的模式：

- **作者动态**：添加一个或多个 GitHub 作者，把他们的公开动态（push、release、PR、issue、fork、star 等）推送到**本页单独选定**的 QQ 会话。
- **仓库订阅**：填 `owner/repo`（分支可留空=默认分支），按分支比对 HEAD SHA；有新提交就推一条汇总（提交数、作者、首行、compare 链接），并可同时订阅 Release 新版本。仓库订阅直接查 commits/releases，不依赖公开事件流，通常更及时。

两种模式都推送到**本页单独选定**的会话；推送会话与项目的群 / 用户白名单完全无关，可手填 `group:群号` / `private:QQ号`，也可从机器人已知会话中挑选。模式在「追踪设置」里选 `authors` / `repos` / `both`。

- 首次加入作者或仓库只建立基线，不会把历史动态刷进群；之后出现新事件/新提交才推送。修改后自动保存并热更新，约 1 秒内提前检查。
- 仓库订阅每轮用上次 HEAD 在最近提交里定位新增提交；一次推了很多或历史被重写时改用 compare 拿准确数量，compare 失败则按最新一条汇总并注明。
- 仓库新提交/新 Release 默认追加 AI 总结（使用「上下文摘要」模型，基于提交信息/发布说明，不拉 diff）；面板可关闭，模型未配置或调用失败时仍发送原文。
- 事件按 id 或 `repo-push:{repo}:{sha}` / `repo-release:{repo}:{id}` 去重并落库，重启不重发；OneBot 离线或某个会话发送失败时保留待推送，恢复后立即补发，且只重试失败的会话。
- 作者动态支持 ETag 条件请求；两种模式都支持 GitHub 限额感知、每轮推送上限、旧事件跳过；可选填 GitHub Token 把限额从 60 次/小时提升到 5000 次/小时。保存新 Token 会清掉旧的限额缓存；私有仓库需要 Token 有 `repo` 权限。
- 面板的「下次检查」每秒本地倒计时；提交信息等不可信文本经消息段转义后再发送。
- 配置保存在 `config/github.yaml`。**填过 Token 后不要再提交这个文件**；发行版模板里的 `token` 为空、`enabled` 为 `false`。

参数、事件类型、仓库订阅流程、状态流转和排查见 [GitHub 动态追踪](docs/github-tracking.md)。

## Token 预算

每次文本生成都会传输出 token 上限。它不是账户额度或累计消耗上限。达到上限通常返回**被截断**的结果而不是调用失败：正文可能不完整，结构化 JSON 可能解析失败，推理模型可能只返回思考。

面板「概览 → 功能开关 → Token 预算」提供七项控件；`0` 表示**沿用该用途原有预算**（发行版模板全部为 0，所以默认行为与没有这段配置完全一致）：

| 用途键 | 调用 | `0` 时的原预算 |
|---|---|---|
| `chat` | 普通回复（含直接视觉回复） | 人格 `maxTokens`，未设时用 `llm.generation.maxTokens` |
| `vision` | 图片结构化描述、OCR | 每图 500，最低 1200、最高 6000 |
| `sticker` | 收藏表情包识图 | 600 |
| `emotion` | LLM 情绪分析 | 200 |
| `facts` | 长期记忆抽取 | 800 |
| `summary` | 上下文摘要 | `llm.generation.summaryMaxTokens` |
| `daily` | 日报生成 | 1200 |

非零值优先于人格预算，重试时也不会超过它，但仍受模型上下文窗口裁剪。保存后下一次调用生效，不需要重启。接口、取值范围（0~131072）与部分更新的语义见 [按用途设置输出 token 预算](docs/token-budgets.md)。

## 常见问题

### 双击脚本出现碎片化命令错误

GitHub ZIP 下载会把 `.bat` 的换行规范成 LF，`cmd.exe` 会把注释和路径片段当成命令执行。本仓库的三个批处理统一为 **ASCII + CRLF**，`.gitattributes` 用 `*.bat -text` 保留原始字节。请通过 Git 或 GitHub ZIP 正常获取，不要用会把换行改成 LF 的编辑器另存。

### 启动日志中文乱码

三个批处理在调用 npm 前切换到代码页 65001，避免中文 UTF-8 日志被系统代码页 936 解码。若你改过脚本，请保留 `chcp 65001` 这一行。

### 面板打不开

- 确认 Agent 已在运行，且没有别的进程占用 3081 端口；
- 默认只监听 `127.0.0.1`，从其他设备访问需要改 `server.host` 并设置 `server.authToken`；
- 查 `logs/` 或控制台里的启动错误。

### SnowLuma 页显示「未安装」或下载失败

- 自动安装需要能访问 `github.com`；公司网络或代理环境下可能失败，此时走「方案 C」手动放置官方包；
- 手动安装必须版本、平台、架构与 `installation.json` 一致，且 `runtime/snowluma/distribution/app/index.mjs` 存在；
- 下载校验失败会在终端里明确指出文件名，不会把半成品当成已安装。

### 提示「账号数据库准备失败，暂不可用并将自动重试」

这是 snowluma 自己的账号数据库工作线程尚未就绪，会按上游流程重试。先看概览和终端里的具体错误；确认使用新版启动包装层后，在面板点 **停止** 再点 **启动**。不要用删除数据库的方式处理。

### 升级后数据库会自动备份吗

会。数据库 schema 升到新版本（当前为 v7）前，程序会用 `VACUUM INTO` 生成 `data/brain.db.pre-v<版本>.<时间戳>.bak`；检测到数据库版本高于程序版本时**拒绝降级启动**，而不是尝试迁移。

### 机器人连不上 QQ

按顺序核对：OneBot 实现是否启动了正向 WS 服务端 → 端口与 `napcat.url` 是否一致 → Token 是否一致 → Agent 日志里是否出现账号信息。群聊不回复时再检查群白名单、是否需要 @、以及该用户是否在黑名单里。

### 图片功能不生效

先确认所选模型真的支持视觉输入，再看日志里是否被判成「不支持图片」。中转站改名导致能力判错时，用 `modelOverrides` 覆盖。
