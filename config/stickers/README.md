# 表情包目录

两种来源，可以混着放：

| 来源 | 放哪 | 标签怎么来 |
|---|---|---|
| 自己收集的图 | 直接丢在本目录 | 文件名是标签（`happy_1.png` → `happy`） |
| **QQ 账号的收藏表情** | 面板「表情包 → 从 QQ 收藏导入」 | **AI 看图后自己写**（推荐） |

支持 `.png` / `.jpg` / `.gif` / `.webp` / `.bmp`。

---

## 一、从 QQ 收藏导入（推荐）

面板「🖼 表情包」→「⬇ 从 QQ 收藏导入」。

它做的事：调 NapCat 的 `fetch_custom_face_detail` 拿到你账号收藏的表情列表 →
**把图下载到 `config/stickers/qq/`** → 写进 `manifest.json`。

> **为什么必须下载**：NapCat 给的是腾讯 CDN 的临时地址，**带签名会过期**。
> 只存 URL 过一阵就全是死链，所以导入 = 拉列表 + 立刻落盘。

文件名是 `qq_<md5前12位>.<ext>`，所以**重复导入是幂等的** ——
同一张图永远算出同一个文件名，不会堆一堆副本。

依赖 NapCat 版本：需要含 `fetch_custom_face` 扩展动作的版本。
旧版本会在面板上提示「当前 NapCat 版本不支持读取收藏表情」，不会静默失败。

导入后接着点「🤖 用 AI 识别含义」。

---

## 二、让 AI 看懂表情包

文件名只能给出 `happy` 这种粗标签，但**这张图到底画了什么、什么时候该发**，
得真看一眼图才知道。点「🤖 用 AI 识别含义」，视觉模型会逐张读出四样东西：

| 字段 | 作用 |
|---|---|
| `tags` | 英文小写标签，模型用 `[表情:标签]` 引用它 |
| `desc` | 一句话说清画面内容，**会进提示词**，所以限 20 字 |
| `useWhen` | 什么情境适合发这张 |
| `emotions` | 对应情绪，供「按情绪自动补图」使用 |

结果写进 `manifest.json`，之后不必重跑。已在面板上可逐张「编辑」手改。

**识别用的模型**在「模型接入 → 模型用途 → 图片理解」里选，需要支持看图。
不可用时面板会直接报错说明，不会白跑一遍。

> 实测：我们测过的 6 张图里有 **4 张的 AI 标签跟文件名不一致** ——
> 名叫 `angry_1.png` 的其实是个眨眼笑脸，名叫 `happy_2.png` 的其实在皱眉。
> 这正是需要 AI 看图的原因：**文件名是不可靠的元数据。**

## 三、怎么发出去

两条路，各自可开关（面板「概览 → 功能开关 → 回复行为」）：

### ① 模型自主决定（默认开）

提示词末尾会带上可用标签和描述：

```
happy(3): 蓝色笑脸，圆点眼睛微微笑
speechless(2): 灰色方块面无表情，两眼平直
```

模型觉得该发时在正文末尾写：

```
哈哈哈哈这也太离谱了 [表情:speechless]
```

管道把标记从正文摘掉，**正文照常发送**，然后单独发一条图片 ——
像真人先说话、再甩一张图。标签对不上只记 debug 日志，不发图也不污染正文。

### ② 按情绪自动补图（默认关）

模型没主动发时，命中配置的情绪且强度足够就自己补一张。三道闸门：

- 情绪命中 `autoSend.emotions` 且 `intensity >= minIntensity`
- 距上次发图超过 `cooldownSec`（**防刷屏，最容易被忽略但最重要**）
- 概率命中 `probability`（避免每次同样情绪都发，显得机械）

配置：

```yaml
sticker:
  enabled: true
  manifest: manifest.json
  maxPerReply: 1
  maxTagsInPrompt: 40          # 提示词里最多列几个标签
  descCharsInPrompt: 18        # 每个标签附带的描述截断长度，0 = 不附
  autoSend:
    enabled: false             # 建议先只开 ①，观察一阵再考虑开这个
    emotions: ["sadness"]      # 命中这些情绪才自动发
    minIntensity: 0.55         # 情绪太弱不配图
    probability: 0.35          # 命中后实际发送的概率
    cooldownSec: 180           # 同一会话两次自动发图的最小间隔
    requireDesc: true          # 只发被 AI 理解过（有描述）的图
```

> 建议：`cooldownSec` 不要低于 120。每次都发表情包很容易招人烦。
> `requireDesc: true` 能挡掉"意义不明的图"，代价是没识别过的图不会被自动发。

## 四、把描述回写到 QQ

面板「↗ 把描述回写到 QQ」会把 AI 生成的描述通过 `set_custom_face_desc`
写进 **QQ 自带的收藏表情描述**，这样在手机 QQ 里也能看到这张图是干嘛的。

需要导入时拿到了 `resId` / `md5` / `emojiId` —— 缺一不可，所以只能对 QQ 来源的图做。

---

## 五、manifest.json

`config/stickers/manifest.json` 是**记录实际生效标签与 AI 理解结果**的地方。
规则：**manifest 记录为准，文件名只作缺省**。

```json
{
  "file": "qq/qq_ab12cd34ef56.png",
  "tags": ["speechless"],
  "desc": "灰色方块面无表情，两眼平直",
  "useWhen": "无语或不知该回什么时",
  "emotions": ["neutral"],
  "source": "qq",
  "resId": "...", "md5": "...", "emojiId": "3",
  "analyzedAt": 1790001848898,
  "analyzedBy": "deepseek/deepseek-flash"
}
```

`qq/` 子目录里的文件名是哈希，**不会被当成标签**（否则模型会写出
`[表情:qq_deadbeef]` 这种东西）。所以从 QQ 导入的图在识别之前没有标签 ——
它仍可被「按情绪自动补图」挑中，只是模型不能主动点名它。

目录里有 manifest 没记过的新文件时会自动补一条（`source: local`）。
文件被删但 manifest 还有记录时，面板会显示「文件缺失」，不参与发送。

## 六、换成你自己的表情包

**发行版本目录是空的**（不放任何图片，避免夹带别人的素材）。两种方式起手：

1. **从 QQ 收藏导入**（最省事）：面板「表情包 → 从 QQ 收藏导入」
2. **自己放图**：把图丢进本目录 → 按 `happy_01.png` 这种**有意义的名字**重命名 →
   点「重新扫描」→「用 AI 识别含义」

社区有现成的 DeepSeek「鲸鱼娘 / 蓝色大肥鱼」表情包合集，例如
[deepseek-chan-meme-pack](https://github.com/the-beating-light-of-the-nail/deepseek-chan-meme-pack)
（474 张，含中英文背景说明）。**注意原作者「上善无形」对「溟月」形象采用
CC BY-NC-SA 4.0（署名 / 非商业 / 相同方式共享），商用或再分发前请先确认许可。**

标签用英文小写最稳（模型拼写更可靠），中文标签也支持。
