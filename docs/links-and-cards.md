# 链接与卡片理解

## 已实现

| 输入 | 可以理解的内容 |
| --- | --- |
| 普通HTTP/HTTPS链接 | 静态网页标题、描述、正文，以及来源URL、重定向后URL和读取时间 |
| QQ链接分享`share` | 标题、简介、URL，继续读取目标网页 |
| JSON卡片 | 小程序、新闻/网页、视频、音乐等卡片中的标题、描述、来源和常见目标URL字段；例如`meta.detail_1.qqdocurl`、`jumpUrl` |
| XML卡片 | `title`、`summary`、`source`及目标URL，支持普通字符实体和CDATA |
| 音乐分享`music` | 自定义分享的歌名、简介和页面URL；仅有平台音乐ID时保留ID，不虚构歌名或歌词 |
| 推荐好友/群、位置卡片 | 分享类型、QQ号或位置字段，仅解释现有资料，不发起加好友/加群等操作 |
| 合并转发内的链接/卡片 | 原作者卡片信息保留为转发引用资料，其中HTTP/HTTPS链接可继续读取 |

QQ合并转发卡片`com.tencent.multimsg`仍优先走原有`get_forward_msg`，避免将其误作普通网页。原始卡片消息段保留在转换后的资料中，网页提取结果随原消息行保存，作者、消息ID和话题归属保持不变。

## 使用方法

- 私聊直接发送链接或卡片，可附加“总结一下”“提取要点”“比较这两个链接”等问题。
- 群聊可先发送链接/卡片，再@机器人：“总结刚才那篇文章”。未需要回复的普通群消息不会自动抓取网页。
- 主动回复和被动回复共用固定聊天窗口；回复开始前窗口中的链接可用于理解话题。引用更早的链接/卡片消息也可读取其资料。
- 重启Agent后生效。后台概览的功能设置新增“链接与卡片”组，可设置正文读取开关、数量/字数/下载大小/时限/重定向限制、缓存时间和允许/禁止域名。
- 不需要新增模型接口或API Key。网页提取不单独调用模型；提取结果加入原有聊天模型的上下文，会占用正常聊天token预算。

## 默认设置与读取范围

| 设置 | 默认值 |
| --- | --- |
| 读取链接网页正文 | 开启；关闭后仍可展示卡片已有标题和简介 |
| 每轮不同链接上限 | 3个；当前消息、引用及聊天窗口共享预算 |
| 单页下载上限 | 1MiB |
| 单页正文上限 | 6000字符；总正文预算为链接数量×单页上限 |
| 当前回复全部网页的总时限 | 6秒 |
| 单链接最多重定向 | 3次，每一跳重新校验 |
| 内存缓存 | 5分钟，最多100项，按QQ会话隔离 |
| 域名范围 | 允许域名为空时允许公开域名；禁止域名优先，均包含子域名 |

优先处理当前/引用及最近的消息，在最近20条候选消息内读取链接；每条消息检查前256个消息段，其他原消息段保留。重复URL按去除片段后的地址去重，保留查询参数；超出预算标明未读取，不把跳过内容当作已知正文。

缓存只减少再次分享同一链接的下载。已经写入消息的网页资料是**读取时的快照**，会保留读取时间；需要更新网页时重新发送链接，过期缓存会重新读取。

仅提取静态HTTP文字响应，不运行JavaScript、不登录、不携带Cookie或模型服务密钥。需要登录、反爬验证、脚本渲染的页面，可能只得到标题或简介；会明确说明没有可提取正文。视频、音频、卡片预览图和PDF不在此次网页正文读取范围内，视频卡片标题不等于已经观看视频。

## 地址与引用处理

- 仅允许HTTP/HTTPS默认端口及80/443，拒绝URL内嵌用户名/密码。
- 本机、内网、链路本地、保留地址与IPv6转换地址不读取。域名解析结果含任一被阻止地址即拒绝，并把连接固定到已检查地址，避免二次DNS解析绕过。
- 重定向逐跳复核地址、协议、端口和域名范围；元数据接口、OneBot端口、文件路径等不能通过链接读取。
- 网页和卡片内容带引用资料标记，只作为问题背景，不触发`/forget`等管理指令，不改变@对象或人格。
- 事实抽取排除网页、卡片和转发作者自述，仍可提取分享者附带的本人文字说明。
- 读取失败、超时、截断、无正文和超过上限都有明确标记；不编造未读取的内容。读取期间切换话题会取消旧回复，不把资料写入新话题。


## 验证

执行 `npm run test:links-cards` 运行33项本地模拟检查，涵盖解析、网络限制、上下文、引用、记忆和后台设置。无需新增API Key；此功能不单独调用模型，正常聊天会使用原有模型及上下文预算。
