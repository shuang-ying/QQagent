# 按用途设置输出 token 预算

每次文本生成都会传递输出 token 上限。它不是账户额度、累计消耗上限或单次输入加输出的总额度。推理模型可能将思考也计入服务商的输出预算，具体计费和限制以服务商为准。

达到输出上限时，通常返回被截断的结果，而不是直接调用失败。正文可能不完整；图片、情绪、记忆等结构化 JSON 被截断后可能解析失败；推理模型可能只返回思考而没有正文。已有空正文重试和失败回退保留。模型上下文窗口及请求超时是另外两种限制：历史会先裁剪，系统指令和当前输入仍无法容纳时会明确失败；增加 token 不会增加超时预算。

| 用途键 | 调用 | `0` 时的原始预算 |
| --- | --- | --- |
| `chat` | 普通回复，含直接视觉回复 | 人格 `maxTokens`，未设时用 `llm.generation.maxTokens`（默认 1024） |
| `vision` | 图片结构化描述、OCR | 每图 500，最低 1200、最高 6000 |
| `sticker` | 收藏表情包识图 | 600 |
| `emotion` | LLM 情绪分析 | 200 |
| `facts` | 长期记忆抽取 | 800 |
| `summary` | 上下文摘要 | `llm.generation.summaryMaxTokens`（默认 1200） |
| `daily` | 日报生成 | 1200 |

`0` 保留旧预算及原有扩大预算重试策略。非零值为该用途每次生成的指定上限，优先于人格及调用方原预算，重试时也不会超过它。非零预算仍会按实际模型上下文窗口裁剪，当前实现输出预留最多使用窗口的一半，调整记录在日志中。多次请求或重试的累计消耗可能高于单次上限。向量化、专用 ASR 和 TTS 使用各自的接口、输入/音频限制，不套用这组文本生成预算。

## 面板与 API

后台「概览 → 功能开关」的「Token 预算」组提供七项控件。保存后写入 `llm.tokenBudgets`，下一次调用生效，不需要重启。已有在途 HTTP 请求的参数不会被追改。

每项控件显示「原预算（填 0 继承）」及当前继承/自定义状态。回复和摘要的原预算读取当前全局配置，回复同时提示人格覆盖；图片理解显示按图数计算的规则，不以固定值误代表动态预算。展示不自动改写现有设置。

`GET /api/token-budgets` 返回当前 `budgets`、原始默认规则 `defaults`、有效范围与单位。`PATCH /api/token-budgets` 支持部分更新：

```http
PATCH /api/token-budgets
Content-Type: application/json
Authorization: Bearer <面板认证令牌>

{"budgets":{"chat":4096,"vision":4096,"sticker":3000,"summary":4096}}
```

面板未设置认证令牌且仅监听本机时，沿用原本的本机访问策略；配置了令牌则 GET 和 PATCH 均需认证。支持值为 `0` 至 `131072` 的整数，不接收数字字符串。未知用途、空对象、数组或非法预算返回 400，整批不更新。

成功返回 `ok`、`changed` 和全部当前预算。只修改请求中列出的用途，其他值保留。沿用原有设置校验、原子保存和运行时同步，写盘失败不更新内存配置。也可以通过原有 `POST /api/settings` 修改 `llm.tokenBudgets.<用途>`。

没有硬改生产配置，旧配置不含这组字段时全部默认为 `0`。预算及接口回归已纳入 `npm run test:offline`，专项命令为 `npm run test:token-budgets`。

本次类型检查、构建、完整离线回归与隔离面板回归通过。预算专项验证旧配置兼容、七种调用用途、重试上限、模型窗口裁剪、部分更新、鉴权与原子保存；视觉专项验证预算热更新及旧缓存失效。输出保存在 `runtime/token-budgets/`，未调用真实模型或发送真实 QQ 消息。
