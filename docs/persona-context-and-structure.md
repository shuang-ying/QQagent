# 人格切换上下文与结构化设定

更新日期：2026-10-05。

## 使用方法

Web后台「人格」页面的会话设置提供人格、历史处理方式和「切换」按钮。默认保留历史；可以选择新开话题。

QQ命令：

```text
/persona cool         # 保留当前话题与历史
/persona cool keep    # 明确保留历史
/persona cool new     # 新开话题，旧话题保留
/人格 blue-fish new   # 中文别名
/topics              # 查看话题，可切回旧话题
```

同一/persona权限仍控制查看和两种切换模式，没有新增绕过权限的命令。

## 上下文行为

保留历史：会话与当前话题的人格更新在同一事务中完成，话题曾指定旧人格也不会遮盖此次切换。原消息/事实/摘要不删除。与当前人格ID或内容指纹不符的机器人回复，转为明确标注来源的历史资料，不再作为当前人格的assistant示例。当前同版人格回复保持正常assistant上下文。原始数据库中的角色和内容不变，转换仅作用于模型输入，资料不代表用户发言。旧库没有人格标记的回复按未知来源处理，不猜测身份。标记内容也计入token预算。

新开话题：保留旧话题和原消息，固定旧话题实际人格；新话题指定新人格，从空话题历史开始。/topics切回旧话题恢复旧人格。长期用户事实仍遵循原记忆共享策略，新开话题不等于忘记用户。

成功切换后取消该会话正在生成、排队或等待分片的旧任务，避免之后再发旧人格回复；已经确认投递的片段仍保留来源。更新人格文件后的历史通过内容指纹区分版本；单纯编辑文件没有增加人格版本回滚功能。

摘要输入标记历史机器人来源，提示机器人自称/表演不得作为用户事实；当前提示词声明旧回复/摘要不修改当前身份与口吻。历史资料仍由LLM理解，不保证语义上绝对无风格影响；需要彻底隔离短期历史时使用new模式。

## 结构化设定

后台人格编辑器新增：身份、语言风格、互动习惯、回答原则、情绪回应原则。原systemPrompt继续保留，两者按固定段落拼装。允许只填结构化字段；原始设定与结构化字段不能同时全部为空。旧人格载入时补齐空字段，不改写原YAML。迁移时在面板手动移走重复/矛盾内容，不会自动重写人格。情绪标签对应的emotionModulation、examples、错误文案等字段继续保留。人格文件保存采用原子写入。人格只是回答设定，权限仍由QQ账号和命令权限配置执行。

## 数据库与部署

该功能引入时数据库 schema 升到 v4，新增 messages.persona_id 和 persona_fingerprint（当前 schema 为 v6）。只给新确认投递的机器人回复记录来源；用户消息不标记为人格消息。旧消息保留，来源为空。启动新程序时在迁移事务前自动备份旧库；旧版本程序会拒绝打开较新 schema，回滚需使用兼容备份。不需要手工迁移，也不需要修改原人格或配置。


新增 12 组专项测试覆盖兼容拼装、切换保持与新建、事务失败、生成中取消、上下文标记及预算、投递来源、迁移备份、API/QQ/Web 和编辑器提交。专项命令 `npm run test:persona-context`，已纳入 `npm run test:offline`。

上述人格来源字段自 schema v4 引入，当前 schema 为 v6；启动新程序时会在迁移事务前自动备份旧库，旧消息原文与空的来源字段都会保留。
