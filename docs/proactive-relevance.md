# 主动插话：相关性判断优化

实施日期：2026-10-05。

## 修改后的判断

相关性不再用全部记忆关键词的命中比例计算，而是分别评估当前人格兴趣和允许使用的记忆证据。强证据不会因为用户拥有更多无关记忆而被稀释。相关分数只影响现有 relevant/hybrid 分支，不改变概率、访问权限、冷却、回复优先级或图片流程。

### 人格兴趣与表达匹配

后台「人格」→编辑，新增「感兴趣的话题」。每行一个话题，用 `|` 或 `｜` 分隔同一话题的表达，例如：

```text
编程|写代码|coding
摄影|拍照
天文|观星
```

最多32行、每行2～100字符，每行匹配最多12个表达。以 persona.proactiveTopics 保存到原有人格 YAML，API读回和文件加载保持一致；后台保存后人格热重载，判断立即采用新值。旧文件没有该字段时默认为空，不改写现有人格文件。兴趣的主名称也加入人格提示词，使回复口吻和判断所用兴趣一致。

不从身份、语言风格或原始指令文本自动猜测兴趣，避免“不要聊编程”变成“喜欢编程”。已有 triggers.keywords 可以作为较弱的兼容信号。少量内置相关表达支持编程/写代码、向量化/文本嵌入等；自定义表达以后台填写内容为准。英文检查词边界并统一大小写、全角字符，避免 ai 匹配 rain、coding 匹配 decoding。

### 当前话题与记忆证据

- 当前话题仅使用当前会话最近10条记录中的最后6条用户消息，并丢弃超过2分钟的消息；每条评分最多读取末尾2000字符。
- 最新消息优先。前两条消息以时间衰减后的35%权重提供背景，旧相关话题通常无法单独跨过默认0.6阈值。
- “具体怎么做”“然后呢”等明确承接表达，可继承近期话题的85%权重；时间越久继承越弱。这是有限规则，不是完整指代解析。
- 每位最近参与者最多20条事实，最多10位用户；只使用有效、非私密、置信度至少0.6的事实，并遵守现有 crossScopeSharing 设置。none 不跨会话，identity-facts 只跨会话使用标记可共享的事实，full 允许非私密跨会话事实；本群非私密事实仍可使用。
- 过滤“用户、喜欢、今天、问题”等泛词；单个两字常见记忆词通常不足以触发高相关分支。
- 中文重叠二字词合并成同一证据，防止同一短语被重复计分；依据匹配的具体程度、独立证据及记忆置信度评分，不使用无关关键词总量作分母。
- 遗忘、私密标记、人格切换和编辑会在下次判定生效，没有相关性缓存造成旧内容残留。

## 分数与诊断

显式兴趣直接匹配基准0.85；内置相关表达折为85%；兼容触发词基准0.65。记忆单个短词基准0.5、具体短语0.72、多处独立证据0.8，乘以表达匹配强度和置信度系数；人格及记忆共同命中可加0.06，总分上限1。背景分数再乘承接及时间系数。阈值继续使用现有 relevanceThreshold。

debug日志增加分数、来源persona/memory/none、是否继承背景、事实ID、人格ID以及发言/放弃原因，不记录事实正文。关闭主动发言时提前返回。

## 成本、验证与限制

此版本采用本地规则和有限同义表达，不新增 LLM/embedding 请求，不新增依赖或数据库迁移。它不是通用语义理解，隐喻、复杂指代及未配置的同义表达仍可能漏判；高相关仍不等于适合打断他人。普通概率分支仍会按原配置触发。

新增 14 组专项测试，覆盖旧人格兼容、表达边界、同义表达、泛词与重复证据、无关记忆稀释、换题与追问、私密/失效事实、跨群隔离、人格热重载、话题隔离、API 持久化和 Web 保存。专项命令 `npm run test:proactive-relevance`，已纳入 `npm run test:offline`。

不需要改动既有数据、配置、人格或日志；不需要重启以外的额外操作。重启加载新代码后即可在后台配置兴趣。
